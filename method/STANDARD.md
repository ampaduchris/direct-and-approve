# Build standard

Copied from the private authority on 2026-11-22.

Every public repo meets this at v1.0. The published method repo carries a scrubbed copy; this file is the authority.

## Verification tiers (every session)
| Tier | Question |
| --- | --- |
| V1 | Does it exist and run at all |
| V2 | Does it do the thing |
| V3 | Does it fail correctly |
| V4 | Does it match the spec, line by line for the requirements touched |
| V5 | Did it break what already worked (full suite) |
| V6 | What did it not verify |

Tier table in every PR body, one row per tier, no blank rows. Columns: Tier, Check run, Command, Result (PASS, FAIL, NOT VERIFIED), Evidence (CI run link or pasted output line).

## Files every repo carries
- `docs/spec.md`: the sole authority; prompts never override it. Requirements carry `REQ-###` and MUST or SHOULD. It ends with an evidence section: what was measured, when, with which versions, and what was not checked.
- `docs/BUILD-LOG.md`: append-only, read first, written last. One row per session: date, session id, model, effort and its source, minutes taken, tiers passed, NOT VERIFIED count, PR link. A spec adopted from a frontload draft says so with the draft's model and date.
- `docs/DEVIATIONS.md`: every departure from spec, numbered, with reason. Any hand edit to code by the owner is logged here.
- `docs/reviews/<session-id>.md`: the independent review's numbered findings.
- `CLAUDE.md`: the rules an agent follows in this repo.
- `README.md`: claim, demo, "Verify it yourself" (three commands that reproduce the headline numbers, exercised in CI), status line, limits, the disclosure line, the authorship note.
- `SECURITY.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, licence, PR template, `portfolio.yml`.
- `docs/REASONING_AUDIT.md` only where the build publishes factual content.

Status line, one of: "Status: active." "Status: released, dependencies reviewed monthly." "Status: finished, last verified on <date>."

Authorship note: "The code here was generated by Claude Code under my direction. I wrote the requirements and approved each change. The law on copyright in machine-generated code is unsettled. I license whatever rights I hold under the licence in this repository."

## Repository settings (scaffold session)
- Ruleset on `main`: pull request required, no approval count, required status checks, merge commits only, no force push, no bypass. Created once, after the scaffold PR has merged and the checks exist.
- Secret scanning, push protection, Dependabot alerts and private vulnerability reporting on. Wiki and projects off. Delete branch on merge.
- Description: the claim, then the proof, in one sentence. Five to seven topics, always including `claude-code` and `spec-driven-development`. Homepage: the site's project page once it exists.

## CI
- Python: the project's minimum (3.11) up to the newest release for which every dependency publishes wheels. Node: the two newest long-term releases. Record the versions chosen in the first BUILD-LOG row.
- Actions pinned to full hashes with the release in a comment; runner image pinned; `permissions: contents: read` at workflow level, with wider permissions only on the release job; 10-minute timeout on the test job; concurrency group cancelling superseded runs; no secrets in the test job; tests run from the lockfile.
- A weekly scheduled run only while the build is CURRENT. Removed at release.
- gitleaks on every PR.

## Controls
| Id | Control | Mechanism | Gate |
| --- | --- | --- | --- |
| R1 | Requirement traceability | Tests are tagged with requirement ids; `scripts/trace.py` prints the matrix and fails CI on an untested MUST | CI |
| R2 | Mutation testing | mutmut or Stryker on the deterministic core. A floor only where the spec sets one; otherwise the score and the surviving mutants reviewed are reported | Release |
| R3 | Property-based tests | Hypothesis or fast-check on parsers, scorers, geometry | CI |
| R4 | Eval harness | `evals/` with cases including planted errors, run on Inspect AI. Planted-error cases must pass 3 of 3. Scored cases report minimum, median and maximum; a regression is a median drop of more than 5 points in 100. Every judged check ships two known-bad outputs that the judge must fail 3 of 3 before its scores count. The baseline file records runner, model ids and date. Runs locally on the owner's key, never in CI | Release |
| R5 | Privacy scrubber | Local: `tools/scrub.py` on the tree, the PR body and commit messages before every push. CI: gitleaks | Every PR |
| R6 | Model provenance | The BUILD-LOG row | Every session |
| R7 | Independent review | One session per build on a model that differs from the author of the thing reviewed. It reads spec and code only, adds `docs/reviews/<session-id>.md`, and opens an issue for each must-fix finding | Once per build |
| R8 | Owner approval | The owner writes a comment on each PR naming what was checked, then merges. The ruleset enforces the pull request and the checks; nothing enforces the attention, so the time from opening to merge is published on the site | Every PR |

## Web-app additions (TypeScript)
Accessibility check (axe) in Playwright on every route, zero serious or critical issues. Link check. Lighthouse is reported, not gated.

## Release
PyPI packages publish by trusted publishing from the release job. No other signing step. No Scorecard badge: run Scorecard once at release and fix what is cheap. No social preview image.

## Maintenance
Dependabot for the package manager and for GitHub Actions, grouped, monthly. For each update PR: CI green, the action's hash matches its tag, release notes read for breaking changes to what the repo uses. Claude posts the check as a comment; the owner approves and merges.

## `portfolio.yml`
Fields, all required: `name`, `pitch` (one sentence), `stack` (list), `tests` (integer), `release` (tag), `released_on` (date), `demo_url`, `repo_url`, `example_pr_url`. Stale means `release` differs from the repo's latest release tag.

## Definition of done for v1.0
All MUSTs traced and passing; mutation result reported and any floor met; eval baseline committed where a model is called; scrubber clean; README complete with a 60-second demo recording (Playwright for web apps, a scripted terminal recorder for command-line tools); CHANGELOG and tagged release; BUILD-LOG complete; review findings closed or logged as deviations; `portfolio.yml` present.

## Runtime model policy
Bring your own key. Default path is offline or a free tier; Claude or OpenAI pluggable through the user's key. CI never calls a model.
